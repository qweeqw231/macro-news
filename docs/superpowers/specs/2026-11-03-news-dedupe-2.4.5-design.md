# 2.4.5：同文多频道去重

日期：2026-11-03
状态：已实施

## 1. 现象

2026-11-03 14:02，要闻流同一标题出现两次：

```
今天 14:02  华尔街见闻  全球   科创50跌超5%，创业板指跌近3%，算力硬件股持续下挫，深南电路、景旺电子、光迅
今天 14:02  华尔街见闻  A股    科创50跌超5%，创业板指跌近3%，算力硬件股持续下挫，深南电路、景旺电子、光迅
```

## 2. 根因（逐段核查）

1. **来源侧**：直接请求华尔街见闻 API 验证（非看前端）。同一篇快讯同时出现在
   `global-channel` 与 `a-stock-channel`：
   - `id=3193103`（全球）`uri=/livenews/3193103`
   - `id=3193102`（A股）`uri=/livenews/3193102`
   - `display_time` 相同（`1793685758`），正文逐字相同。
   同一篇被改写后还会再出现一组（正文从简版变完整版，URL 复用 `…102` / `…103`）。
2. **去重侧**：`src/collect.mjs` 只按 `it.id` 去重（`merged` Map 与归档 `seen` Set），
   而两条的 id 不同 ⇒ 都保留。
3. **数据侧**：归档里确实有 4 条（两版正文 × 两个频道），id 不同、URL 成对相同、
   `ts` 与 `time` 相同。
4. **前端侧**：前端不做二次分组/合并，只是按 `latest.json` 原样渲染 ⇒ 看到两条。

## 3. 规则

新增 `src/news-dedupe.mjs`（纯函数、无 IO）：

| 键 | 条件 | 说明 |
|---|---|---|
| URL | 归一化后相同（去协议、末尾斜杠、utm/ref 等追踪参数，保留 `?id=` 等业务参数） | 最硬的同文证据 |
| 正文 | 同来源 + 同 `ts` + 归一化正文（去空白/标点，前 300 字） | 两个频道的逐字同文 |
| 标题 | 同来源 + 同 `ts` + 归一化标题 | 覆盖「简版改写成完整版再发」 |

合并时频道取舍（`channelRank` 越小越具体）：

```
A股 / 中国 (0) > 国内财经 (1) > 外汇 / 大宗 / 美股 (2) > 全球 (3) > 其它 (1.5)
```

同频道保留正文更长的一条；仍相同则保留先出现的，保证顺序稳定。
**不同 `ts` 不合并**：同一句话在不同时间发布可能是更新或更正。

## 4. 自愈

写归档时改为：

```js
const mergedItems = dedupeItems([...items, ...existing.items])
```

即本轮新增与**已有归档**一起重新合并。只要该日下一次采集写入（哪怕没有新条目，
只要合并后条数变化），重复条目就会被清掉。实测当日归档 `782 → 755`。

局限：长期不再更新的历史日期不会被主动扫描；如需全量清理，可手动对
`data/archive/*.json` 跑同一函数（本次不扩大范围，避免每次采集读写 60+ 文件）。

## 5. 测试

`tests/news-dedupe.test.mjs`（9 项）：

- 真实事故：两个 id / A股+全球 → 1 条且归 A股；
- 真实事故升级版：两版正文 × 两频道（4 条）→ 1 条完整版；
- 同 URL 不同标题 → 1 条；
- 不同正文/不同时间 → 不误合并；
- 非重复项顺序不变、空输入安全；
- 频道优先级、URL/文本归一化；
- `collect.mjs` 两处调用接线锁定。
